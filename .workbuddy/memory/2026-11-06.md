## 导出包（单文件 exe）悬崖全丢：glb 索引 0 个

3. `export_presets.cfg` 的 `include_filter` 加 `assets/models/_index.txt`

**教训**：凡是靠「扫目录」找资源的地方，导出包里都会归零；要用清单或 `ResourceLoader.Exists`。

## 纠正：`_models.txt` 清单是多余的，改回直接拼路径

`export_presets.cfg` 的 `include_filter` 回到 `assets/terrain/*`；删除 `converted/_models.txt`。

**验证**（空目录跑导出 exe）：`悬崖格 2400 / 斜坡过渡 20 / 地表 6/6 / 抠掉 2413`，

## Demo 阶段：导出 BootyBay.tscn

新增 `--export-scene=地图|场景`，产物：
```

Godot/Demo/BootyBay/{ground,cliff,water}_material.tres   ← 材质球

```

**几何复用 `ViewportPanel.BuildMapTree(terrain)`**（新加）：内部就是 BuildMapCliffs → BuildMapTerrain
→ BuildMapWater，和编辑器里跑的是同一套 1273 行代码，不是重写。

**踩到的三个坑**：
1. `Texture2DArray` **存不进资源**：它是渲染资源，Godot 没有序列化器，存 .res 只剩尺寸、像素全丢，
   加载时报 `_create_from_images` 失败。改成把每层导出成 PNG，场景脚本运行时拼回数组。
   → 因此导出要跑两次：第一次写 PNG，等 `--editor --quit` 导入后再跑一次，.tscn 才带贴图引用。
2. **`Node3D.SetScript()` 会重建 C# 实例**，之后手里的 `root` 句柄失效（`ObjectDisposedException`）。
   改成直接 `new BootyBayScene()` 当根节点，再把子节点搬过去，属性直接赋值。
3. **headless 拿不到纹理像素**：`GetLayerData` 在 dummy 渲染器下返回空，导出必须用带渲染器的模式跑。

**图层数量**（之前理解错了）：地表 array 是 **193 层 64×64 小瓦片**（6 张 512×256 图集 × 8×4
= 192 + blight 1），不是 6 层；悬崖 2 层、水面 45 层。

**相机**：`LoadScene` 要补 `_dist=20*CellSize / _yaw=180 / _pitch=-0.977rad`，
否则用字段初值（35°/-46°/2900）算出来的同机位差一截。

**验证**：`--scene=res://Demo/BootyBay.tscn --cam=-21759,1551,9375` 截图，
与运行时构建排圈差 **0.07**，与 HiveWE 排圈 **0.44**（比运行时的 0.53 还低）；`[DEMO]` 日志确认
193/2/45 张图层合入材质。

## 新目标：场景显示单位（从「笔刷能刷出来的内容」扩展）

### 数据链路
```
war3mapUnits.doo → typeId + 位置/朝向/玩家
  → UnitUI.slk 的 file/modelScale（单位）或 ItemData.slk 的 file/scale（物品）
  → assets/converted 的 .glb
```
坐标：`格 = (doo 的 x,y − terrain.offset) / 128`；BootyBay offset = (-12544, -6400)。
Godot 位置 = `(-(x-offsetX), z, y-offsetY)`，朝向 `rotation.Y = π + angle`（x 取反带来的 180° 补正）。

### BootyBay 实测
61 条 = 59 单位 + 2 个 sloc（起始点，不渲染）；19 种类型（绵羊 nshe×8、金矿 ngol×6…）；
玩家分布 12(中立敌对)×36、15(中立被动)×23、0/1 各 1（都是 sloc）。
**这张图验证不了队伍色**（可见单位全是中立）。

### 两个解析 bug（都是影响全部 2048 个模型的）
1. **LAYS 块头第二个字段是「层数」，不是字节长度**。原来把 1 当长度，`body+length` 直接错位，
   导致 filterMode/textureId 全部读错 —— VillagerWoman 的身体用了 gutz（血液）贴图。
   正确：`LAY S | count | layer[count]`，每层以 inclusiveSize 开头（28 字节 + 子块）。
2. **filterMode 映射全错**（1~6 全当 BLEND）。正确：0=OPAQUE、1=MASK(cutoff 0.75)、2=BLEND、
   3-6 是加法/调制（glTF 无对应，暂退化成 BLEND）。羊的「花白噪点」就是 1 被当成 BLEND 导致的。

材质层数分布：单层 2862、双层 420、三层 3（423 个模型是多层，目前只取第一层）。

- 材质层数分布：单层 2862、双层 420、三层 3 —— 多层模型只取第一层（通常是主贴图 + 队伍色/发光）。
