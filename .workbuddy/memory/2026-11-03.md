踩过的坑（都已修复）：
1. `Utilities.h` 自定义 `std::hash<QString>` 与 Qt 5.15 内置特化冲突 → 用 `QT_VERSION` 条件编译包住。
2. `Base/Map.cpp:240` 用了从未声明的 `cpos` → 改为 `pos - origin`（`origin` 即视点）。
3. Bullet 默认 `/MT`，与 Qt 的 `/MD` 冲突 → `-DUSE_MSVC_RUNTIME_LIBRARY_DLL=ON` 重编。
4. Bullet `BUILD_EXTRAS` 有编译单元会卡死（cl CPU 0 十几分钟）→ 只编三个核心 target。
5. CascLib config 强制 `find_dependency(ZLIB)` → 先编 zlib。
6. glm 默认开测试会 FetchContent 拉 googletest → `-DGLM_BUILD_TESTS=OFF`。
7. `windeployqt` 只在 Qt bin 里找依赖 → 把 `qt5advanceddocking.dll` 复制进 Qt bin。
8. 沙箱里 `reg.exe` 被拦导致 `vcvars64.bat` 探测不到 SDK → 手工拼 INCLUDE/LIB/PATH（仅沙箱内需要，用户正常终端不受影响）。

产物：`D:\WorldEditor\build_ninja\HiveWE.exe`（6.6MB，Ninja+RelWithDebInfo），Data 与 Qt 运行时已就位。

追加：首次启动报「找不到 Qt5PrintSupport.dll」。原因是 `qscintilla2_qt5.dll` 链接了 printsupport 模块，而 `windeployqt` 只分析了 exe，没分析同目录的 DLL。补拷 `Qt5PrintSupport.dll` 后，用 dumpbin 递归校验 8 个本地二进制 → ALL_DEPENDENCIES_OK。正确做法是 `windeployqt HiveWE.exe qscintilla2_qt5.dll qt5advanceddocking.dll` 一次作用到三个二进制。

追加：用户游戏目录 `D:\War3_1.31` 是经典 1.31 布局——`.build.info` 在根目录，`Data\` 下只有 config/data/indices。而 `Hierarchy::open_casc()` 固定打开 `<dir>/Data`（重制版布局），报 `Error opening "...\Data" with error:2` 后退出。已在 `CASC::open()` 加回退：失败且父目录有 `.build.info` 就退一级重试。

**真正的根因（关键）**：CascLib 的 `LPCTSTR` 是 `TCHAR*`，由编译期 `UNICODE` 宏决定，而导出的函数名不带 A/W 后缀。库按 ANSI 编、应用按 Unicode 编（HiveWE 的 CMake 定义了 `UNICODE _UNICODE`）→ 链接正常，运行时库把 `wchar_t*` 当 `char*` 解析，路径变乱码 → `error 2`。修法：`-DCASC_UNICODE=ON` 重编 CascLib。
判断技巧：同一个库写个 `main()` 传 `char*` 路径，能开就说明库是 ANSI 版。
修好后程序可正常启动（实测运行 12 秒不退出，GL 上下文创建成功）。1.31 的 CASC 内部路径确实用 `war3.w3mod:` 前缀（探测确认 `war3.w3mod:units/unitdata.slk`、`war3.w3mod:scripts/common.j`、`war3.w3mod:UI/MiscData.txt` 均可打开）。

**同一类坑第二处**：StormLib 的 `STORM_UNICODE` 默认也是 OFF。应用定义 UNICODE 而库编成 ANSI → `SFileOpenArchive` 把 `wchar_t*` 当 `char*`，症状是能进界面但打开任何 MPQ 地图都弹 `Opening the map archive failed. It might be opened in another program.`（官方 0.6 却能开）。修法：`-DSTORM_UNICODE=ON` 重编（build_stormlib.bat）。用 UNICODE + `/MD` 的测试程序验证 `D:\War3_1.27a\Maps\(2)BootyBay.w3m` 可正常打开。
注意：写这类测试程序时要 `/MD`（cl 默认 `/MT`，会报一堆 `__imp_fopen` 未解析），并加 `/D__STORMLIB_NO_STATIC_LINK__` 关闭 pragma 自动链接。
另：`timeout` 杀不掉 Windows 下的 GUI 进程，重链接前要用 taskkill 清掉残留的 HiveWE.exe，否则 `LNK1168`。

**绿色网格线**：`Map.cpp:277` 原本无条件调用 `physics.dynamicsWorld->debugDrawWorld()` + `physics.draw->render()`，把 Bullet 碰撞体画成线框，颜色写死在 `Data/Shaders/physics_debug.fs`（`vec4(0,1,0,1)` 纯绿）。官方 0.6 发布包的 Data 里**没有**这两个 shader（对比 141 vs 99 个文件，只差 Tools/backups/* 和这两个 shader），所以官方版画不出来。已包进 `if (render_debug)`，默认关，与 F3 Debug 开关联动。
