## 11:00 converted 整棵树移出仓库 + 解压版本号机制

**目标**：`Godot/assets/converted` 全部当成解压产物，不进仓库；解压工具加版本标记，避免重复解压。

**1. .gitignore**
原来是一堆按扩展名的精细规则（glb/png/tscn/tres/import/wav…），改成整棵树：
```
/Godot/assets/converted/*
```
必须用 `/*` 而不是 `/Godot/assets/converted/`——排除目录本身后 git 不再进这层，下面的白名单全部失效。

**白名单（唯一例外）**：`Tables/*.cs`、`Texts/*.cs`、两个 `.gdignore`。
原因（实测）：这些 `.cs` 不是运行期资源，是 slk/txt 生成的 C# 源码，被
`MapDocument.cs`、`TerraCli.cs`、`CliffTextureSet.cs`、`AssetCli.cs` 直接引用并编译进程序集；
`extract.bat` 第 1 步就是 `dotnet build`，把它们 untrack 会让新克隆的仓库 build 直接失败，
也就没法运行生成它们的 `--table-export/--text-export`（鸡生蛋）。136 个已跟踪文件正好全是这些，无需 untrack。

**2. 版本标记**（`Godot/src/Core/Tools/AssetStamp.cs`，版本号唯一来源 `AssetStamp.Version = 1`）
- `--asset-stamp=目录[|源目录]`：整轮解压成功后写 `converted/_extract-version.txt`
  ```
  version=1
  time=2026-11-07T09:47:34+08:00
  source=D:/War3_1.27a
  models=2048
  images=4283
  ```
- `--asset-status=目录`：末行固定 `STATE=FRESH / STALE / MISSING / INCOMPLETE`
  （FRESH 还要求 `Units/Textures/Tables/Texts` 目录都在）
- 改动转换产物（glb 结构 / 材质 / 动画 / 图片格式）时必须把 `Version` 加一。

**3. 脚本**（extract.bat / extract.command）：新增 `[2/7] 版本检查`，FRESH 直接 `[SKIP]` 退出；
新增 `-force` / `--force` 强制重跑；末尾 `[7/7]` 写标记。两个脚本保持纯 ASCII（cmd 按 GBK 读，中文会拆错行）。
`.gitattributes` 补 `*.command/*.sh text eol=lf`——写成 CRLF 会让 macOS 的 shebang 带 ^M 跑不起来。

**实测**：`extract.bat -noimport` 全流程 3 秒结束（build 1s + 状态 1s），输出
`[STAMP] 标记版本 1，当前版本 1，解压时间 …，模型 2048 个` + `STATE=FRESH` + `[SKIP]`；
把标记改成 `version=0` 后正确返回 `STATE=STALE`；findstr 分支（MISSING/FRESH/-force）三项单测通过。

## 11:20 打包增量化：代码包 + 外置资源包

**实测基线**（`--export-pack "Windows Desktop"`）：冷缓存 14m12s，热缓存 10m23s，产物 459 MB。

**且 C# 程序集在 pck 内**（原始字节能看到 `.godot/mono/publish/x86_64/`），所以 `--export-patch` 补不了代码
（程序集在任何 C# 代码运行前就加载了）。

**方案：代码和资源分两个包**
- `Godot/export_presets.cfg` 新增两个预设：
  - `"Windows Debug"`：`exclude_filter="assets/converted/*"` + `embed_pck=true` → 只带代码的 exe

  `res://assets/converted` 不存在时（= 调试包）挂载 exe 同目录 `assets.pck`（replace_files=false，
  不能覆盖 exe 内嵌的程序集），再按名字挂 `assets_patch*.pck`（replace_files=true）。
  发布包资源内嵌 → 直接返回。
- `export.bat` 三种模式：默认=调试代码包（**17.8 s / 209 MB**）、`-assets`=资源包（16 min，带“没变就跳过”）、

**顺带查出并修掉的三个打包才暴露的 bug**（开发环境全部看不出来）：
1. **白模**：导出把 tscn 转 scn 时**丢弃子场景实例内部节点的属性覆盖**，`geoset*` 的

   → `ModelBundle.SceneText` 末尾输出 `[editable path="Model"]`；已有 2047 个模型 + 24 个 Colorways

   （修好 1 之后才暴露，直接从“全白”变成“41 个单位被跳过”）。

   `ModelBundle.TexturePng` 改成 `ResolveConverted()`，逐段按磁盘大小写解析，找不到退回占位贴图。
3. **`buildings/` 与 `Buildings/` 是两棵重复目录树**（各 1857 个文件，内容相同）——大小写混乱的根源，
   提取器写了两份。**未修**，需要动 `War3Extract` / `ImageBatchConverter` 的落盘路径。

**验证**：`WorldEditor.exe`(209MB) + `assets.pck`(460MB) + `assets_patch.pck`(12MB) 启动后

## 14:20 导出过滤语义纠正 + 大包导出退化的证据

**用户指出 `include_filter` 用法错误**，确认：`include_filter` 是「把非资源文件也带上」的后缀过滤（`*.txt` 之类），
不是资源筛选。引擎里的四种导出模式（从二进制字符串挖出）：
```
Export all resources in the project                         all_resources
Export all resources in the project except resources checked below   exclude（+ export_files 选中列表）
Export selected scenes (and dependencies)                   scenes
Export selected resources (and dependencies)                resources（+ export_files）
```
`exclude_filter` 是「Filters to exclude files/folders from project」，glob 写法合法（exe 预设用的就是它，15s 完成）。
试过 `exclude` 模式 + `export_files` 列 Demo/Main.tscn/icon/shaders/fallback/.godot/mono —— Godot 接受该结构，
但同样跑不动。

**真正的阻塞：大包导出在本机退化到 ~1MB/分钟**（12:03 那次只要 3m19s）。
证据：CPU 空闲（16s/976s）、采样 30 秒 **读 0 次 / 写 0 次**、Defender 实时保护=关闭、
可用内存 38G、`.godot/exported` 缓存删掉重建仍然一样；每次都在写到 **86~92MB 后** 开始龟速
（日志显示仍在推进，只是 1 分钟 100 行）。`[editable path="Model"]` 已排除（带/不带实例化都是 20.6ms）。
判断是导出线程卡死/停滞（0 I/O 但进度微动），建议重启机器后再试，12:03 那次证明同样的配置可以 3 分钟跑完。
