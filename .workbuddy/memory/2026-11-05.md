## 第九轮：鼠标悬停 Tooltip 全黑

现象：悬停按钮弹出的提示框整块黑，看不到内容。

根因（有实测数据）：Godot 的 tooltip 弹窗在 `Viewport::_gui_show_tooltip_at` 里 `tooltip_owner->add_child(popup)`，
**挂在被悬停的控件下面**，所以会继承 UiTheme。但我们的 Theme 只定义了通用 `Label` / `PanelContainer`，没定义
`TooltipPanel` / `TooltipLabel`：
- 面板回退到 `PopupPanel`（UiTheme 里没有 → 引擎默认深色 `0.1,0.1,0.1,0.6`）
- 文字回退到 `Label`（我们设成 `#141414` 深色）
→ 深底 + 深字 = 全黑。另外引擎默认 tooltip 字体是 Open Sans，**没有中文字形**（探针打印 `有中文=False`）。

修法：
1. `UiTheme.Build()` 显式定义 `TooltipPanel`（白底、`#b9babb` 边、圆角 3、内边距 8/5）与
   `TooltipLabel`（`#141414`、字号 12、字体 Microsoft YaHei）。
2. `Main._Ready` 设 `ThemeDB.FallbackFont = UiTheme.Font` / `FallbackFontSize = 12`，兜住不继承 UiTheme 的弹窗。

验证手段：新增 `--tooltip-probe`，按引擎同样的节点结构（`PopupPanel` variation=TooltipPanel + `Label`

## 第十三轮：MPQ 读写打通（C# Core）

新增 `Godot/src/Core/`：`Formats/Mpq`（Crypto/Archive/Writer）、`Formats/W3x`（W3e/W3i/Wts）、`Map/MapDocument`、`Tools`（MpqCli/MapCli）。

关键实现细节（都是踩出来的）：
- **MPQ 哈希**：`seed2 = ch + seed1 + seed2 + (seed2 << 5) + 3`（是 seed2 不是 seed1）。用 StormLib 常量校验：
  `Hash("(hash table)",3)==0xC3AF3770`、`Hash("(block table)",3)==0xEC83B3A3` 全中。
- **加密表**：hash/block 表可能整体加密，用 `Hash("(hash table)",3)` 解密；明文表要能识别（按条目合理性判断）。
- **文件密钥**：`key = Hash(name,3)`；带 FIX_KEY 时 `key = (key + blockOffset) ^ block.FileSize`（未压缩大小！）。
- **扇区偏移表解密用 `fileKey - 1`**（StormLib SBaseCommon.cpp:1322），扇区数据用 `fileKey + i`。这条错了会读到天文数字偏移。
- **未压缩块**（只有 EXISTS 标志）没有扇区表，直接读 csize 字节。

验证（(2)BootyBay.w3m）：7 个文件的 md5 与 mpyq 完全一致；listfile 解密出 24 个名字。

另存为：`--map-saveas=<src>|<dst>|<name>`。结果写到 `Documents/Warcraft III/Maps/(2)BootyTest.w3m`，

## 第十五轮：1.31 不显示地图 → 表必须加密

现象：另存为的 (2)BootyTest.w3m 在 1.31 客户端列表里看不到。

根因：StormLib 的 `LoadMpqTable` 对 hash/block 表是**无条件解密**（`if(dwKey != 0) DecryptMpqBlock(...)`，
调用处固定传 `g_dwHashTableKey` / `g_dwBlockTableKey`）。我们之前写的是**明文表**，StormLib 把它当密文解开 → 乱码 →
归档不可用 → 客户端静默跳过。我们自己的读取器带明文探测，所以自测能过，掩盖了问题。

修法：`MpqWriter` 写出前用标准密钥加密两张表：
`MpqCrypto.EncryptBlock(hash, Hash("(hash table)",3))`、`EncryptBlock(block, Hash("(block table)",3))`。

独立校验（python 解密新文件）：hash 表 26 个有效槽位、块索引全部 < 26、无越界块、块 0 = off 0x20/flags 0x80000200。

教训：**自己写的读取器不能当写回的验证器**，要对着 StormLib 的实际行为（源码）校准。

## 第二十轮：地形四角混合 + 角点法线 + 边界黑雾 + 两个窗口接线

用户给了三张对比图（HiveWE / 我们 / 官方 WE），指出地表"格子不连续"。

### 三个原因（按影响排序）
1. **UV 步进错了**：512×256 的地表贴图是 **8 列 × 4 行 = 32 个 64×64 变体**，
   我按 4×4、步进 0.25 算，每块横跨两个变体 → 纹理碎成噪点。
   正确：`u = (variation & 0x1F) % 8 * 0.125`，`v = (variation / 8) * 0.25`。
2. **每格只选一张纹理**：改成顶点带四角索引（CUSTOM0 = RgbaFloat），
   shader 用 `fract(world/128)` 双线性权重混合四层。
3. **法线是每格平面法线**：`GenerateNormals` 对独立顶点算出的法线在格边界突变。
   改成角点法线（用左右/上下邻居高度差），相邻格共用同一角点法线。
   实测相邻角点 layer 差为 0 的占 92%，所以"尖刺"不是层高造成的。

### 边界
不是"边界墙"——是我之前说错了。官方 WE 是**边界黑雾**：w3e 的 boundary 标记 + 外圈渐隐压暗。
实现：顶点传"到边界还有几格"（CUSTOM1.x），shader 里 `fade = clamp(cells/3)` 后平方。

## 第二十一轮：变体左右半修正 + 相机高度约束滚轮 + 去掉黑雾

用户反馈：草地近看有深绿/黑方块、过渡不自然；相机最高高度对滚轮无效；黑雾这轮不查。

### 关键修复：贴图变体有左右两种内容
512×256 切成 8 列 × 4 行 = 32 个 64×64 变体，但**左右两半不一样**：

## 地表「八向连续」：贴图左右半区的真实用途（2026-11-05 晚，第三轮）

用户提醒「地表没做八向连续」。查清了 War3 地表贴图的结构：512×256 = 8×4 个 64×64 小块，**左右两半用途完全不同**（实测 alpha）。

| 位置 | alpha | 用途 |
|---|---|---|
| 右半 c4–c7（16 块） | 全部 255 | 纯色块，提供纹理变化 |
| 左半 c0–c3（16 块） | 0–255 渐变 | 遮罩块，索引 = 四角组合的 4 位 mask（bit0 右下 / bit1 左下 / bit2 右上 / bit3 左上） |

四角同地表 → mask=15 → 第 15 块 alpha 恰好 255；只有左上角是它 → mask=8 → 只留左上角的渐变遮罩。**这就是格子之间柔和过渡的来源。**

我们的实现：
- 底层 = `BaseLayer(最小 tileID) + VariationLayer(左下角 variation)` → 纯色块
- 第 2–4 层 = `BaseLayer(tileID) + mask` → 遮罩块
- shader 用**上层** alpha 混合：`c.rgb = mix(c.rgb, l1.rgb, l1.a)`

**HiveWE 的 bug**：它写 `color = color * color.a + next * (1 - color.a)`，用**当前层** alpha 当比例。底层是纯色块（alpha=1），下一层直接被乘 0，四层叠加实际不生效 → 它的地表就是硬边拼贴。照抄必错。

改完之后：草地采样均值 `[26,97,20]` vs 参考 `[26,100,19]`，泥土/草地/雪地/岩石的过渡都变成斑驳羽化。

踩坑记录：
- 一开始把底层也改成 mask（`LayerWithMask(baseId)`），过渡出来了但整片草地纹理固定成第 15 块（丢失 variation 变化）。
- 只把 `VariationLayer` 改成用左半区（`return variation`）会露出大片黑块——左半区是遮罩块，alpha=0 的地方透出背景。

## 坐标系手性：地图左右镜像（2026-11-05 晚，第四轮）

用户指出「Godot 显示的地图和 HiveWE 左右反了」。确认属实，而且这是前几轮「怎么调都不对」的根因之一。

**根因**：HiveWE 是 z-up 右手系，Godot 是 y-up。把地图 (x,y) 直接映射成世界 (x,z)、高度映射成 y，即 `(x,y,z)→(x,z,y)`，**交换两个轴 = 反射变换（det = -1）**，手性翻转 → 画面左右镜像。

**检测手段**：`tools/mirror_check.py` —— 提取水域掩码，比较「原样 IoU」和「水平翻转后 IoU」。翻转后更高就说明镜像了。实测 62.7% → 83.8%。

**修法**（收口在 `AddVertex` / `AddWaterVertex`）：
- `st.AddVertex(new Vector3(-position.X, ...))`，法线 x 一并取反
- 每个三角形的后两个顶点对调（镜像后绕序反了，cull_back 会掉面）
- 相机 target 的 x 取反

**顺带修的两个「看起来对其实错」**：
1. **相机中心要用整数除法**：HiveWE 是 `position = (width/2, height/2)`，width 是 int，193/2=96 不是 96.5。用 96.5 整幅画面偏半格（1600 宽视口上 22 像素）。改完最佳平移从 dx=-22 变成 dx=0，IoU 83.4% → 87.2%。
2. **地表 UV 要 v 翻转**：HiveWE 用 `UV = (x, 1-y)`。不翻转的话，因为每个 64×64 小块有上下方向性，草地上会出现规则横向亮暗条纹。
3. **地表列表要按 w3e 头顺序排**，不能按角点出现顺序——四层叠加「底层取编号最小」的编号就是这张表的索引。

**结果**：水域重合度 87.2%（无平移），草地采样均值 `[25,98,18]` vs 参考 `[26,100,19]`。

剩余差异：浅滩上 1–2 个深蓝色硬边方块、崖台位置差半格、水面覆盖略大 4%。

## 小地图方向 / 斜坡变悬崖 / 黑色地块（2026-11-05 晚，第九轮）

## 坡面「折痕 vs 曲面」：四边形对角线切法不同（2026-11-05 晚，第十三轮）

用户：我们的斜坡是直线折面、和地面有硬折痕；HiveWE 是曲面斜坡。

排查（重要，别重复走弯路）：
1. 先把 HiveWE 加上 `--no-water`（`Map::render_water`），两边都关水面比地形：
   区域均值 34,109,22 vs 34,109,21 → **地形几何是一致的**，不是坡度公式问题。
2. 逐格核对：`final_ground_height = height + layer_height - 2`，两边完全一样；法线、光照也一致。
3. 真正的差异：**四边形三角剖分的对角线方向**。HiveWE 的 `Utilities.h quad_indices = {(0,3,1),(1,3,2)}`
   沿 **p10–p01 反对角线**切；我们沿 p00–p11 主对角线切。坡度过渡处两条对角线一个出屋脊、一个出凹谷，
   看起来就是「折面 vs 曲面」。
4. 改完对角线注意绕序：镜像后要重新排列，否则整片地面被背面剔除（画面全黑，我第一次就踩了）。

结果：默认视角水域 IoU 89.5% → **89.8%**；用户机位无水渲染与 HiveWE 分块差异明显变小；冒烟 33/33。

副产品：HiveWE 新增 `--no-water` 参数（`render_water`），以后排查地形和水面可以分开看。

## 斜坡（ramp）到底怎么实现的：HiveWE 侧射线实测

结论：斜坡不是 shader 里的曲面，是 CPU 侧角点高度 + 每格 2 个三角形的分段平面。

- HiveWE 地表是一片 1×1 的四边形实例网格，`terrain.vs` 只 `texelFetch` 顶点高度（`height_cliff_texture` = `ground_corner_height`），
  三角剖分沿 **(1,0)–(0,1) 反对角线**（`Utilities.h quad_indices={(0,3,1),(1,3,2)}`）；`terrain.fs` 只做 4 层混合 + 固定方向光。
- 斜坡的关键在 `Terrain::update_ground_heights`：**斜坡入口格的底层角点高度 +0.5**（`ramp_height = 0.5f`），
  于是 1 层高差摊到 2 格、每格半层 → 约 24°，起坡/收坡各一个折点，中间是直线。
- 我方 `ViewportPanel.GroundWorld` 只算 `height + layer - 2`，漏了这 0.5：
  斜坡只剩 1 格、约 43°，同一位置比 HiveWE 低 32–64 世界单位。
- 副作用：斜坡下段会掉到水面（166.4）以下（(60,35) 地面 136 vs HiveWE 200），
  所以那块"水面糊住斜坡 + 直岸线"也是这个原因。

调试工具（已加）：
- HiveWE `--probe=x0,y0,x1,y1,steps`：沿直线打 Bullet 射线，打印碰撞面与渲染三角面高度（实测逐点一致）。
- HiveWE `--target=x,y,z`：直接指定轨道中心并关掉贴地（`TPSCamera.ground_locked`），可复现 Godot 任意机位。
- `tools/w3e_probe.py`（离线高度剖面/列斜坡格）、`tools/draw_tile_lines.py`（把格线投到截图上定位折痕）。
