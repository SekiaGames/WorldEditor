## HiveWE 笔刷与光标错位（已修，4ba7d79）

现象：1.31 原生 BootyBay 里笔刷方块偏离光标约 1-4 格；自带 Test Map 正常。

定位方法：临时加 F4 采样日志（%TEMP%\hivewe_mouse.log 记录鼠标、相机、射线、命中点），
再把命中点反查 war3map.w3e 高度后统计——**这是关键**，纯读代码猜不出来。

结论：物理高度场用 `corners.height` + 刚体原点 z=4，渲染用
`ground_corner_heights = final_ground_height() = height + layer_height - 2.0`，
两者只在 layer==6 时重合。相机俯角 31° 时 1 单位高度差 ≈ 0.83 格横向偏移。
Test Map 是平地、层高恒定所以看不出。

修法：碰撞体改用 ground_corner_heights，刚体原点 z 改 0。
验证：命中点 z - 可视高度 从 2.01 → 0.05。

## 事故：HiveWE 启动即崩（0xC0000409），元凶是 war3map.wtg

现象：用户退出程序后再也打不开。实测每次启动 ~5 秒后静默退出。

定位（结论可靠，均有数据）：
- PowerShell `Start-Process -Wait` 取真实退出码 = `0xC0000409`；事件日志 1000/1001：
  ucrtbase.dll + c0000409 + P9=7 → 是 **abort()**（未捕获异常 → terminate），不是栈溢出。
- 把 build 复制到临时目录做隔离：用仓库原始 `Data/Test Map/war3map.wtg` → 正常运行；
  只把 `build/Data/Test Map/war3map.wtg` 换进去 → 必崩。**确认 wtg 是元凶**。
- 结构对比（python 解析）：原版 cat=6/trig=17/comment=3/script=0/var=211/element_count=232；
  坏版 18/5/4/211/239。分类计数被改写，导致 `load_jass` 按 wtg 的 triggers 去切 wct 时整体错位 → 越界抛 `out_of_range`。
- 关键代码缺陷：`Triggers::build_trigger_data()` 末尾直接 `map_file_write("war3map.wtg")`（`Triggers.cpp:513`），
  而 `Triggers::load()` 为拍快照会调它（`Triggers.cpp:133-136`）→ **每次打开地图都会重写一遍 wtg**
  （实测：md5 不变、mtime 每次启动都变）。写盘副作用 + 分类计数往返不一致 = 自毁。
- 原版 wtg 往返是字节一致的（md5 不变），所以「打开」本身安全，怀疑坏文件来自 23:15 那次 Save Map
  （或之前打开过 Trigger Editor 把 4 个元素判成 script、2 个判成 comment）。

处理（已做）：坏 wtg 备份到 `build/_backup/2026-11-04-2315/war3map.wtg.corrupt`，
把仓库原始 `Data/Test Map/war3map.wtg` 覆盖回去，**保留用户 23:15 写的 wct**（实测该组合可正常启动）。
未改任何代码。
