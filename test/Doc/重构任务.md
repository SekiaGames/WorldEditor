# 重构任务（第二轮：以客户端 vendor 为底）

判据见《重构原则.md》。一句话：逻辑以客户端为唯一基准，Launcher 只允许两类本地形态——载入（pck 资源、C# 表配置）与表现（Godot 节点）。

---

## 0. 边界

**容器层本地化，内容层照客户端。**

- 容器层指「从哪儿拿字节、怎么画上屏」：MPQ、Godot pck/gmap、GL、OpenAL、WinForms 界面。这批东西在 Launcher 里换成 Godot 形态，不保留桌面实现。
- 内容层指「拿到字节之后怎么解析、怎么合并、什么时序」：SLK/TXT 解析、物编合并、W3X 记录解析、`World.Step`、技能与 buff 生命周期。这批原样照客户端，Launcher 侧不重写。
- 可运行版 `Launcher` 越界的地方在内容层：`War3MapUnits` 208 → 241 行、新增 `W3xBinaryReader`/`W3xBinaryWriter` 473 行、`War3ObjectData` 754 → 897 行。

**入口改注入。** 原则第 4 条：纯数据保留，入口改注入，表与规则类不能自己读盘。`War3ObjectData.Load(war3Dir, mapPath)`、`War3GameplayConfig.Load(war3Dir)`、`War3MapUnits.Load(mapPath)` 改成收注入源；`MergeSlk`/`MergeTxt`/`MergeMapObjectData`/`Parse` 主体不动。

**禁止两件事**：往客户端类型上加投影成员（`Unit.Position`/`Player`/`View`/`MoveTarget`、`Ability.Type` 那一批，上一轮 5264 个错误的来源）；另写一套同功能实现。

**工程文件不承载取舍。** `Launcher.csproj` 与两个参考工程保持同构：

```xml
<Project Sdk="Godot.NET.Sdk/4.7.2">
  <PropertyGroup>
    <TargetFramework>net8.0</TargetFramework>
    <EnableDynamicLoading>true</EnableDynamicLoading>
    <RootNamespace>Launcher</RootNamespace>
    <Nullable>annotations</Nullable>
    <LangVersion>latest</LangVersion>
    <NoWarn>$(NoWarn);CS9113;CS0108</NoWarn>
  </PropertyGroup>
</Project>
```

不写 `Compile Remove`，不写 `PackageReference`。出现 `PackageReference` 就说明底座混进了不属于 Launcher 的容器层实现（`SharpZipLib`/`System.IO.Hashing` 来自 MPQ，`SharpCompress` 来自 mod 归档，`System.Drawing.Common` 来自桌面截图，`Silk.NET` 来自 GL）。

## 2. 阶段与任务

每阶段收尾：`dotnet build` 0 错误，并与可运行版 `Launcher` 跑同一张图对输出。阶段内任务按序做。

### R1 底座裁剪

目标是把底座里不属于 Launcher 的容器层实现删掉，让工程回到"只剩内容层"。这一阶段不保证编译绿：删掉 MPQ 相关实现后 `Src/Resources` 会断，断裂由 R2 补。

| 任务 | 做什么 | 为什么 |
|---|---|---|
| R1-1 | 删 `GameCore/L1_Adapter/RHI.OpenGL/`（10 个文件） | Silk.NET GL 后端。底座对 RHI 的唯一消费是 `ITexture`（`L2/UI` 的 Fdf 2 处、Frames 6 处、Render 1 处、诊断 1 处），`IRenderDevice`/`IBuffer`/`IVertexArray`/`IShaderProgram`/`IFramebuffer` 在底座里零引用 |
| R1-2 | 删 `GameCore/L0_Foundation/RHI` 下除 `ITexture.cs`、`Enums.cs` 之外的 5 个接口 | 同上，无消费者。可运行版 `Launcher` 的 `L0` 正好只剩这两个文件 |
| R1-3 | 删 `GameCore/L2_Core/MapBrowser/` 的 `MainForm`、`MapArchive`、`BlpDecoder`、`TgaDecoder`、`TerrainParser` | WinForms + System.Drawing。首屏地图选择改成 Godot 界面（R5-4） |
| R1-4 | 保留 `MapBrowser/MapInfoParser.cs` | `MapInfo` 定义在这里，客户端 13 个文件引用；本身不依赖 System.Drawing。R5-4 要用 |
| R1-5 | 删 `GameCore/L1_Adapter/Formats/Jass/JassAotCompiler.cs` 与 `Src/Diagnostics/JassParserTest.cs` | JASS AOT 编译器用 .NET 9 的 `PersistedAssemblyBuilder`，Launcher 不做 JASS；那个测试是它唯一的引用者 |
| R1-6 | 删 `GameCore/L0_Foundation/ThirdParty/War3Net/`（67 个文件 7132 行） | MPQ 容器读取。Launcher 的容器是 pck/gmap。删它顺带退掉 `SharpZipLib`、`System.IO.Hashing` |
| R1-7 | 删 `Src/Resources/War3ModLibrary.cs` | mod 归档（zip/rar），对战不做 mod。删它顺带退掉 `SharpCompress` |
| R1-8 | `Launcher.csproj` 回到与参考工程同构（见第 0 节），删掉所有 `Compile Remove` 与 `PackageReference` | 取舍落在代码树上，不落在工程文件上 |

`System.Text.Encoding.CodePages` 不用加包：`CodePagesEncodingProvider` 在 net8 共享框架里（`shared/Microsoft.NETCore.App/8.0.20/System.Text.Encoding.CodePages.dll`），可运行版 `Launcher` 同样零包引用即可编译 `War3TextEncoding`。

R1 收尾预期：错误从 91 条降到 5 条左右，全部集中在 MPQ 数据源那一族（`War3ResourceManager`、`War3ArchiveLease`、`War3MapResourceAliases`、`War3MapFingerprint`、`War3GameplayConfig`、`IAudioPort`、`TriggerParserTest`），由 R2 处理。

## 4. 验收口径

- 对照运行是唯一可信验收：同图、同参数，比 `--dump-units`、比探针、比截图。可运行版 `Launcher` 就是对照组。
- 错误数不是进度。上千条同一个缺失成员只算一个根因；一条物编列名写错不会报错，却让数值全错。
- 每阶段收尾告诉用户看什么：跑哪条命令、看哪一行日志。

## 5. 遮蔽陷阱

CS0102 / CS0111 会让编译器停止分析该类型的其余成员，错误数骤降看着像进展。上一轮实例：`Unit.Abilities.cs` 一条重复 `Abilities` 让 22832 条错误变成 2 条。

遇到数字骤降，先查是否新增了平行实现，再查语法错误，然后按根因归并。
